# Phase 0 architecture decisions

## Internal TypeScript linking

Internal libraries use stable `@quiron/*` imports mapped to each library's public `src/index.ts` entry point in `tsconfig.base.json`. This is the Nx-native integrated-monorepo approach generated by `@nx/js`: TypeScript resolves the aliases, Nx dependency analysis maps imports to projects, and `@nx/enforce-module-boundaries` applies project tags. Consumers must import a library through its alias, not by relative cross-project paths.

## Tags and dependency policy

| Project | Type tag | Source tag |
| --- | --- | --- |
| `api` | `type:app` | `source:backend` |
| `web` | `type:app` | `source:frontend` |
| `core` | `type:shared` | `source:core` |
| `ambassadors` | `type:domain` | `source:ambassadors` |
| `tasks-agenda` | `type:shared` | `source:tasks-agenda` |
| `seguros-marketing-leads` | `type:domain` | `source:seguros` |

Applications may depend on domain and shared libraries. Domain libraries may depend only on shared libraries. Shared libraries may depend only on shared libraries. Direct domain-to-domain imports are forbidden.

Run `npm run check:boundaries` to execute the negative guardrail, which creates a temporary illegal import and succeeds only when ESLint rejects it with `@nx/enforce-module-boundaries`.

## Nx Cloud

Phase 0 removes the unused `nxCloudId`. Local and CI commands use Nx's local runner without requiring `NX_NO_CLOUD=true`. Nx Cloud can be connected later as an explicit infrastructure decision.
